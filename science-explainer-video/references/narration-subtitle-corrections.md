# 解说原话字幕、读音与措辞纠错

记录所有者 2026-10-16 对通信协议、电流采样、FOC 等视频的通用要求。用于男声讲解及其修订；无配音简约风继续使用场景内短文案，不强加人声逐字稿。后续明确指令优先。

## 字幕必须是声音里的话

“字幕跟声音对上”的明确含义是：**把字幕改成声音的字，完整对应实际解说，不能用概括句替代。** 同时满足文字对应和时间对应。

- 保留实际说出的句子及必要连接词，按自然短语拆成可读字幕；不要只留下关键词、结论、框图说明或重新写的摘要。
- 可以把“八点六六伏”显示为 `8.66 V`、把协议名称写成正确技术拼写；这些是同一内容的书写规范化，不是改写或删减解说。
- 标题可以概括问题，图中标签可以简写，但不能把这些标签冒充完整解说字幕。
- 正文冷白、关键数值和关键词用对象对应的亮色强调；同一句的各色片段、数字、单位和标点共用基线。字幕保持[手机大字规范](line-animation-mobile-type.md#mobile-typography)的粗、大、亮与最多两行，长句拆短，不能缩小字体来容纳整段。

在制作数据中区分三层：

| 层 | 用途 | 约束 |
| --- | --- | --- |
| 解说原文 | 计划让观众听到的完整话语 | 内容经核对，修改时检查实际合成人声是否说对、说全。 |
| 合成输入 | 提供读音、语言或多音字提示 | 可用私有发音提示，但不能将提示用的替代字、拼音或谐音写进字幕。 |
| 屏幕字幕 | 实际人声的完整文字 | 保留原话内容，规范化数值、单位、希腊符号、算法人名、标点与断句。 |

不要直接照搬 ASR 的错别字，例如把“电平”识别成“电瓶”，不能据此改错技术字幕。若人声确实漏词或读成另一个词，先修正该段人声，再更新原话字幕；不能用强制对齐把没有说出的字假装对齐成功。

## 字幕专用：希腊符号与算法人名

所有者于 2026-10-16 将以下两条设为后续视频的通用字幕规则，**不限于 FOC**：

1. **字幕中所有希腊字母的中文译名，直接改为对应标准希腊符号。** 不再保留“阿尔法、贝塔、伽马”这类音译，也不在符号后重复附上中文译名。以下对照是示例，不是只处理这些字母的白名单。

   | 字幕中的中文译名 | 符号示例 |
   | --- | --- |
   | 阿尔法 | `α` |
   | 贝塔 | `β` |
   | 伽马 | `γ` |
   | 德尔塔 | `δ` |
   | 西塔 / 塞塔 | `θ` |
   | 拉姆达 | `λ` |
   | 西格玛 | `σ` |
   | 欧米伽 | `ω` |

   按原变量、公式或上下文确定对应字母、大小写和字形；原本指 `Δ`、`Γ`、`Ω` 时保留大写，不能一律变成小写。其它中文译名同样处理，不能因未列表示例就保留音译。仅在确实指希腊字母时替换，不把“派生”等普通词中的字机械改成符号。

2. **字幕中控制、信号处理领域经典算法相关人名，采用国际通用的标准英文拼写。** 不再使用中文音译，覆盖变换、滤波、控制方法等名称中的人名部分：

   | 算法语境中的中文音译名 | 标准拼写 | 字幕示例 |
   | --- | --- | --- |
   | 克拉克 | `Clarke` | `Clarke 变换` |
   | 帕克 | `Park` | `Park 变换` / `反 Park 变换` |
   | 卡尔曼 | `Kalman` | `Kalman 滤波` |
   | 马姆达尼 | `Mamdani` | `Mamdani 模糊推理` |

   这项规则也覆盖同领域其它高频算法人名，不限于表中四项。遇到未列出的名字，依据原始论文作者署名或权威技术资料核对标准拼写，保持正确大小写；不要凭中文近音猜英文，也不要把其他同音人名误改成表中名字。只替换人名部分，保留实际说出的其它内容。

**这两条仅作用于字幕显示层，包括画面烧录字幕及 SRT / ASS / VTT。保持已有解说读音、说话人、语音内容、解说原文和 TTS 输入；不要因为字幕改成符号或英文而重新配音，也不据此主动改写图内标签、论文题名、直接引文或代码标识。** 两条规则是同一技术内容的书写规范化，不是删减或概括原话。字幕仍依据原始口述文本或可靠的已有时间轴对齐，修改字面写法不应改变既有语音时间。

制作时同步更新实际烧录字幕和字幕文件，检查希腊字形、英文拼写、大小写、实际字体覆盖与换行；在字幕显示层扫描残留音译名，按语境处理。伴随文档里的原解说文字可以保留原读法，不应为了让全文没有中文音译而越过字幕范围。字幕变速严格跟随同一次音视频变速；1.15 倍属于该条 FOC 修订版的选择，不是所有新视频的默认。

## 读音：按词逐项保存，后来的要求覆盖旧的

所有者最终指定如下，覆盖此前“英文都按单词读”的泛化：

| 屏幕名称 | 解说读法 | 合成与检查要点 |
| --- | --- | --- |
| UART | 单词读法，近似 `you-art` | 不逐字母念 U、A、R、T。 |
| CAN | 英语单词 `can` | 不逐字母念 C、A、N。 |
| LIN | 近似英语 `Lynn` | 不逐字母念 L、I、N。 |
| 1-Wire | `one wire` | 屏幕保留数字 `1` 和正确名称。 |
| SPI | 逐字母 S、P、I | 不读英语 `spy`；这是上述单词读法的明确例外。 |
| I²C / I2C | “i 方 c” | 不读“i 平方 c”，也不改念数字 2。 |
| 引脚 | yǐn jiǎo | “脚”读 jiǎo，不读 jué；屏幕仍写“引脚”。 |
| 分量（电流、矢量的分量） | fēn liàng | “分”读一声，不能读成重量语境的 fèn。必要时用私有同音提示“芬亮”，字幕仍写“分量”。 |
| 曲线 | qū xiàn | “曲”读一声，不读 qǔ；发音提示只用于合成输入，字幕仍写“曲线”。 |

保持已确认男声音色和自然中文讲解。对其它未指定的术语按其常用读法处理，必要时查证或试听；不能从这张表推导出所有缩写都读字母或所有缩写都读单词。合成语言/发音提示的改变不能默默切换说话人、降调或改变整片语速。使用实际音频检查读音；自动转写只能提供证据，不能凭它宣称亲耳试听过。

## 措辞与技术名称

- 在所有者原创讲解自己的计算示例时，将“本例”改成“本视频”；按语法使用“本视频中”“本视频中的示例”或“本视频采用……”，避免机械替换成拗口句子。同步修改人声、烧录字幕、字幕文件和相关画面文字，不能只改 SRT。
- 共享推理用“我们”；自己的项目和实验才用第一人称，避免每句反复出现“我”。按明确的当次叙事要求执行，不把通用科普都改成个人经历。
- 标题优先准确、直白的技术名称。UART 速率不匹配的章节写“波特率不一致，为什么会读错？”；图中区分波特率、位周期和采样位置。SPI 等章节真正谈随行时钟时仍用“时钟/采样边沿”，不能把所有“节拍”一律换成“波特率”。
- 不改写直接引用、论文原话、代码标识或原始证据来伪装成“本视频”的成果；具体来源仍放在伴随依据文档中。

## 时间对齐与变速

1. 核对最终使用的人声，确定实际完整文本。对发生变化的段落重新合成或修正，不默默换声。
2. 将人声按本视频确认速度处理，再对这份实际音频做声学短语/字词对齐；也可严密地同步变换既有可靠时间轴。按字数平均分配只能作为草稿，不能代替交付前同步检查。
3. 字幕短句的入场、停留和退场对应实际说话区间。淡入淡出不能提前消掉最后几个字，也不能让下一句提前替换当前句。长句在自然停顿处分割，保留完整内容。
4. 音频、场景、烧录字幕及 SRT/ASS/VTT 共用时间轴。纳入独立封面、暂停、段间空白、重新合成后的时长和帧率取整；不要把人声加速两次，或只改字幕文件。
5. 检查实际编码成片的片头、改动段、中段与片尾。确认字幕原话覆盖、术语读音、入出点，以及后半段没有累计漂移。检查上方先出现、留出阅读时间、下方再出现而上方保留；这不等于两者不能同时可见。

默认仍是正常速度。通信视频的 **1.1 倍**、电流采样视频的 **1.15 倍**、它们的 **无 BGM** 是各自明确选择，不是新的全局默认。常规修订保留该视频已确认的速度、音色、配乐、封面层级、画幅、配色及泛光；新视频依照当前 brief 和原有选择规则。

区别于上述单片设置，所有者明确将**线条动画**设为今后所有视频的持续选择。按[统一线条动画规范](line-animation-mobile-type.md)直接执行，不再询问或主动制作其它动画风格；两种解说方式继续独立选择。

## 修订与交付检查

- 多音字纠错应优先重新合成包含该词的完整语句或自然短语，保留连读与韵律。避免把孤立字词拉伸后硬拼回句中；若拼接造成卡顿、停顿或音色突变，应扩大到完整语句重录，再对最终人声重新对齐字幕。语音转写只能核对文字，不能独自证明声调、连读和衔接正确。

- 搜索原创脚本和所有观众可见文字中待纠正的措辞与同类问题；明确改动的是字幕内容、发音、时间还是全部，不能只修其中一层。
- 字幕导出与画面烧录采用同一份短句事件；对照解说原话核对无遗漏，数值规范化保持原值、符号、精度和单位。
- 在最终编码视频中检查修改处的完整句子，以及最长字幕、公式、彩色片段基线、手机阅读尺寸；遵循[手机排版与线条动画验收](line-animation-mobile-type.md#encoded-review)。
- 修改段长或插入封面后复查后续同步和前后转场；检查稳定帧无旧句、重影或多余残留，不能只检查过渡中间的混合帧。
- 伴随文档记录实际速度、音色配置、发音映射、依据和已做的检查；画面不添加“正常速度/已确认男声”等制作状态。未做的检查不能写成已通过。
